# Sample Selection and Data Preparation

This directory contains four sequential scripts that identify eligible Peruvian road-infrastructure tenders, acquire their published schedules and supporting documents, count consultation/observation records, and construct the analytical dataset.

The study covers the procurement-notice cohort selected for 2020–2025.

## 1. Workflow

Run the scripts in this order:

| Step | Script | Purpose |
|---|---|---|
| 00 | `00_select_sample.py` | Link source datasets and apply the study selection criteria |
| 01 | `01_download_pdfs.py` | Extract published schedules and acquire the corresponding PDFs |
| 02 | `02_count_queries.py` | Obtain one combined consultation/observation count, Q |
| 03 | `03_integrate_results.py` | Integrate Q and schedules, apply quality controls, and export the common analytical cohort |

Scripts 00, 02, and 03 process local files. Script 01 requires access to SEACE.

These scripts prepare the data. Statistical estimation, Monte Carlo simulation, discrete-event simulation (DES), and model validation belong to subsequent stages.

## 2. Requirements

Use a local Python environment with the following packages:

```bash
python -m pip install pandas numpy openpyxl pymupdf playwright
python -m playwright install chromium
```

No AI API key is required for the standard workflow.

Script 02 includes optional local OCR and AI functionality. These options require additional configuration and are not enabled by the commands presented below.

## 3. Required Inputs and Directory Locations

Before running Script 00, place the 12 annual OECE-SEACE Excel datasets directly in `00_data/`:

- Six Procurement Notice datasets, one for each year from 2020 through 2025.
- Six Contract Award datasets, one for each year from 2020 through 2025.

Expected naming patterns include:

```text
CONOSCE_CONVOCATORIAS2020_*.xlsx
CONOSCE_ADJUDICACIONES2020_*.xlsx
```

The same patterns apply to the remaining study years. Each `*` represents the variable suffix generated by the portal; it is not part of the literal filename.

See [the source-data instructions](../../00_data/README.md) for acquisition details.

| Location relative to the repository root | Content |
|---|---|
| `00_data/` | Raw annual Excel inputs |
| `01_scripts/01_sample_and_data/` | These four scripts |
| `02_results/01_sample_and_data/` | Generated datasets, acquisition evidence, checkpoints, and audits |
| `03_logs/01_sample_and_data/` | Execution logs |
| `05_pdfs/` | Canonical PDFs accepted during acquisition |

Generated directories are created by the scripts as needed.

**Keep acquisition evidence and checkpoint directories.** They support resumption, document validation, and schedule integration.

## 5. Script 00 — Sample Selection

### Purpose

`00_select_sample.py` reads the annual source files, links procurement notices with contract-award records, and applies the implemented selection rules.

The rules cover:

- Valid procedure/item linkage keys.
- Contractual object: works (`Obra`).
- Selection procedure: public tender (`Licitación Pública`).
- The 2020–2025 notice cohort.
- Contextual screening for the defined road-infrastructure scope.
- Exclusion of descriptions that do not establish the required scope.

**No monetary cutoff is applied.** Reference amounts remain available for subsequent analysis.

Date completeness is not used as an exclusion criterion at this stage. Final temporal eligibility is assessed by Script 03 using the schedules acquired by Script 01.

### Execution

```bash
python 01_scripts/01_sample_and_data/00_select_sample.py
```

### Main outputs

Under `02_results/01_sample_and_data/`:

| File | Content |
|---|---|
| `00_1_sample_selection.xlsx` | Selected procurement procedures and retained source information |
| `00_2_sample_selection_flow.xlsx` | Selection funnel, criteria, and audit information |

The script also saves detailed audit files and execution information.

## 6. Script 01 — Schedule and PDF Acquisition

### Purpose

`01_download_pdfs.py` reads the selected procedures from Script 00 and searches SEACE for their corresponding fiches.

It extracts published schedule rows, audits document listings, and attempts to acquire the target consultation/observation document or the corresponding no-formulation act.

Accepted PDFs are stored in `05_pdfs/` using canonical names:

```text
<procedure_code>.pdf
<procedure_code>_ACTA.pdf
```

The `_ACTA` suffix identifies an act acquired in place of the consultation/observation response document. Its content must still be assessed by Script 02 before Q can be assigned.

### Execution options

Attempt up to 50 pending procedures:

```bash
python 01_scripts/01_sample_and_data/01_download_pdfs.py --batch-size 50
```

Running without arguments also uses a batch size of 50:

```bash
python 01_scripts/01_sample_and_data/01_download_pdfs.py
```

Attempt all pending procedures:

```bash
python 01_scripts/01_sample_and_data/01_download_pdfs.py --all
```

Process one selected procedure:

```bash
python 01_scripts/01_sample_and_data/01_download_pdfs.py --procedure-code 1085253
```

Refresh a procedure's fiche while allowing reuse of an existing validated PDF:

```bash
python 01_scripts/01_sample_and_data/01_download_pdfs.py --procedure-code 1085253 --refresh-fiches
```

Search one procedure using an explicit year:

```bash
python 01_scripts/01_sample_and_data/01_download_pdfs.py --procedure-code 1085253 --year 2024
```

An explicit `--year` requires `--procedure-code` and restricts the search to that year.

### Automatic adjacent-year search

Without an explicit year override, the script searches:

1. The initial search year.
2. The previous year, if the completed search returns `PROCEDURE_NOT_FOUND`.
3. The following year, if the previous-year search also returns `PROCEDURE_NOT_FOUND`.

This fallback does not apply to every technical or download failure.

### Resuming acquisition

Rerun the same batch or `--all` command after an interruption or incomplete execution.

The script uses saved state and document validation to skip completed, unchanged cases and retry pending cases. A PDF is not accepted solely because a file with a matching name exists.

Previously downloaded files may be reused when they satisfy the implemented validation checks.

### Main outputs

Under `02_results/01_sample_and_data/01_acquisition/`:

| Output | Content |
|---|---|
| `01_1_acquisition_status.xlsx` | Consolidated acquisition status, schedule stages, document publications, and existing-PDF audit |
| `01_1_acquisition_status.csv` | Procedure-level acquisition status |
| `state/` | Per-procedure checkpoints |
| Execution evidence directories | Extracted schedule evidence and acquisition records |

The acquisition workbook includes:

- `procedure_status`
- `schedule_stages`
- `document_publications`
- `existing_pdf_audit`

### Practical recommendations

- Keep the computer awake and maintain an internet connection.
- Do not close or interact with the browser windows controlled by the script.
- Avoid running multiple acquisition instances simultaneously.
- Close generated Excel workbooks before execution.
- Allow sufficient time for a large collection. Runtime depends on portal response, connectivity, document sizes, and retries.

An interruption does not require restarting acquisition from the beginning.

## 7. Script 02 — Consultation/Observation Counting

### Purpose

`02_count_queries.py` reads PDFs accepted by Script 01 and obtains a single combined count:

**Q = number of numbered consultation/observation records.**

Consultations and observations are not exported as separate explanatory counts.

### Counting rules

- Count document records, not occurrences of the words “consulta” or “observación.”
- Validate the detected record-number sequence.
- Assign **Q = 0** only when document content explicitly confirms that no consultations or observations were submitted.
- Leave Q missing when the document is unavailable, its identity is unresolved, or its count cannot be verified.
- Never replace an unavailable count with zero.

The output retains all procedures selected by Script 00.

### Execution options

Process all available accepted PDFs:

```bash
python 01_scripts/01_sample_and_data/02_count_queries.py
```

Attempt ten documents:

```bash
python 01_scripts/01_sample_and_data/02_count_queries.py --batch-size 10
```

Recount one procedure:

```bash
python 01_scripts/01_sample_and_data/02_count_queries.py --procedure-code 595604 --force
```

In the reference pilot, procedure `595604` returned **Q = 15**, matching visual inspection.

A single-procedure run retains the complete selection in the exported register, but only attempts the requested procedure. Matching successful checkpoints for other cases may be reused.

### Resumption

Successful counts are reused when the document fingerprint and counting configuration match.

After an interruption, rerun the command. Changes to the counting rules or configuration can trigger reprocessing.

### Main outputs

Under `02_results/01_sample_and_data/`:

| File or directory | Content |
|---|---|
| `02_1_query_counts.xlsx` | Procedure-level Q, document information, and counting status |
| `02_1_query_counts.csv` | CSV counterpart |
| `02_2_processing_summary.xlsx` | Status summary, unresolved cases, descriptive statistics, and directory audit |
| `02_query_counts/state/` | Per-procedure counting checkpoints |

## 8. Script 03 — Integration and Final Quality Control

### Purpose

`03_integrate_results.py` combines:

- The selection and source variables from Script 00.
- The fiche schedules and acquisition validation from Script 01.
- The combined Q measurement from Script 02.

It exports both a complete integrated register and the common eligible cohort for subsequent DES and Monte Carlo analysis.

### Final eligibility controls

A procedure must satisfy all of the following:

1. Q has status `OK`, is a nonnegative integer, and is consistent with the document type.
2. The accepted document identity and fingerprints agree with the current local PDF.
3. The fiche has an extracted schedule and the required identity-validation chain.
4. Start and end dates are available and unambiguous for:
   - Formulation of consultations and observations.
   - Absolution of consultations and observations.
   - Integration of terms.
   - Submission of offers.
   - Evaluation/qualification.
   - Award of the buena pro.
5. Available Script 01 summary dates agree with the extracted schedule rows.
6. Calendar-date boundaries follow the required nondecreasing sequence.
7. Adjacent intervals sum to the total modeled duration.

Zero-day intervals are allowed when boundaries fall on the same calendar date.

No monetary threshold, arbitrary duration cutoff, date imputation, or additional explanatory-variable requirement is introduced.

### Modeled time horizons

The primary horizon is:

**Start of consultation/observation formulation → end of the award stage.**

The script also retains:

**Close of consultation/observation formulation → end of the award stage.**

Durations are calendar-date differences, without an inclusive `+1`. Time-of-day values are not used to calculate fractional-day durations.

Adjacent intervals include both stage durations and waiting periods between stages.

### Interpretation of temporal exclusions

Missing-date exclusions refer to the extracted evidence available to the pipeline. They do not, by themselves, prove that the original portal contains no date.

The chronological control requires a sequence without overlaps between the modeled stages. A procedure excluded for an overlap is incompatible with this sequential specification; its dates are not automatically considered erroneous.

### Execution

```bash
python 01_scripts/01_sample_and_data/03_integrate_results.py
```

### Main outputs

Under `02_results/01_sample_and_data/`:

| File | Content |
|---|---|
| `03_1_integrated_dataset.xlsx` | All selected procedures, source variables, quality flags, and exclusion reasons |
| `03_2_model_ready_dataset.xlsx` | Procedures satisfying every final eligibility control |
| `03_3_quality_control.xlsx` | Funnel, exclusions, schedule evidence, linkage checks, definitions, and input fingerprints |

CSV counterparts are also generated for the integrated and eligible datasets.

**Use `03_2_model_ready_dataset.xlsx` or its CSV counterpart for the subsequent common-cohort analysis.**

Source fields are preserved with prefixes:

- `source00_`: sample-selection information.
- `source01_`: acquisition and schedule-summary information.
- `source02_`: document-counting information.

The definitive combined count is `queries_observations_count`. Dates used for the final temporal controls have the `schedule_` prefix.

The quality workbook distinguishes:

- `first_reason`: mutually exclusive first exclusion reasons.
- `all_reason_counts`: all failed controls, whose counts may overlap.

## 10. Troubleshooting

| Problem | Action |
|---|---|
| `ModuleNotFoundError` | Install the required packages using the same Python interpreter used to run the scripts |
| Playwright cannot find Chromium | Run `python -m playwright install chromium` |
| Script 00 cannot find an annual Excel file | Check its location in `00_data/`, naming pattern, year, and `.xlsx` extension |
| Multiple annual source files match the same pattern | Keep exactly one intended source file for each dataset/year combination |
| `PermissionError` when writing Excel | Close the generated workbook and rerun the affected script |
| Internet interruption or browser timeout during acquisition | Restore connectivity and rerun Script 01 |
| `PROCEDURE_NOT_FOUND` | Allow the automatic adjacent-year search; use a justified explicit year override if needed |
| `PDF_IDENTITY_MISMATCH` | Keep the case unresolved; do not rename or relabel the file to force acceptance |
| `DOWNLOAD_ERROR` | Retry Script 01; persistent portal failures remain documented |
| Q remains missing | Inspect the Script 02 status and summary; missing does not mean zero |
| Scanned PDF has insufficient text | Review the status; optional OCR requires local Tesseract configuration and language data |
| PDF was replaced after acquisition or counting | Rerun the relevant upstream validation and counting stages; do not bypass fingerprint checks |
| Script 03 excludes a procedure | Read its first and additional exclusion reasons in the quality workbook |
| Duplicate procedure codes stop integration | Inspect upstream outputs; do not remove duplicates arbitrarily |
| A selected procedure is missing from an upstream output | Inspect the linkage audit and regenerate the relevant upstream output |
| An extra PDF appears in `05_pdfs/` | Inspect the directory audit; files outside accepted acquisition records are not automatically counted |

After changing an upstream input or rerunning an upstream stage, rerun the affected downstream stages so that the integrated outputs remain consistent.

## 11. Interpretation and Reproducibility

### Published schedules

The extracted fiche dates are **published schedule dates**, not independently verified actual event timestamps.

The pipeline preserves the label:

```text
published_schedule_not_verified_actual_events
```

Consequently, the prepared durations describe the published schedules used in this dataset. Claims about actual elapsed procurement times require corresponding event evidence.

### Q as a proxy

Q is an observed document-based count used as a proxy in the study. It is not a direct measurement of all dimensions of information asymmetry, and the preparation pipeline does not establish a causal effect.

### Common analytical cohort

The final eligible dataset applies the same Q and date-completeness requirements to procedures intended for both simulation approaches.

Passing these controls establishes computational eligibility. Distribution fitting, treatment of dependence between intervals, predictive validation, and simulation assumptions must still be assessed in the analytical stages.

### Local files

Raw annual Excel inputs and downloaded PDFs are not distributed as part of the public repository. Researchers obtain them using the documented acquisition workflow.

Keep the source exports, acquisition evidence, checkpoints, generated audits, and logs locally to support reconstruction and verification.
